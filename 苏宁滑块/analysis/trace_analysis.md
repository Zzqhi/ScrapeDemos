# 苏宁滑块 JSVMP Trace 分析

## 概况

- 总 opcode 执行量: **20,645 条**
- 唯一 opcode 种类: **55 种**
- 时间跨度: **5,716 ms**
- mousemove 循环 pattern 重复: **51 次**（对应约25次 pointermove 事件 × 2组处理）

## 关键发现

### 1. 轨迹数据处理算法
每个 mousemove 的处理流程:
```
取模(%) → 属性访问 → 除法(/) → 减法(-) → 属性设置 → 比较(>=) → 方法调用
```
这表明轨迹坐标经过了**数学变换**后存储，不是直接存原始坐标。

### 2. 提交数据构造
尾部的 opcode 序列包含:
- 3次相同的 pattern: `übpa..pMſ\.\..o......üÀL.\..........üÀL.^ś..ś..ś..ś..ś..ÀL.\¸.oo...üb*vMÎſ.E.ðſØŘb.bØŘ`
- 这可能对应 3 个数据字段的编码（如: x轨迹、y轨迹、时间戳）
- 最终 `Eaa...ØŘEaa...ØŘ` — 两次方法调用后创建对象，即最终的加密结果

### 3. 没有 XHR 发出
滑动完成后没有 XHR 请求 → mouseup/pointerup 没有正确触发提交，或者需要额外的验证步骤。

## 下一步建议

1. **在 mouseup handler 处设断点** — 捕获提交时的完整 trace + XHR payload
2. **Hook `ß`(取模)和 `Ė`(除法) 的操作数** — 还原轨迹加密公式
3. **在 XHR.send 处断点** — 直接拿到最终提交的 payload 格式
4. **对比不同滑动轨迹的 trace** — 找出哪些 opcode 处理的是动态数据 vs 静态逻辑
